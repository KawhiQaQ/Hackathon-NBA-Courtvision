# 出手快照格式 v1.0

下载页面“方法与数据 → 下载导入示例”可获取完整真实样例。`data/normalized/` 是分析器的全部输入，不需要任何连续轨迹文件。

## 文件结构

```json
{
  "schemaVersion": "1.0",
  "game": {
    "id": "your-game-id",
    "home": "主队",
    "away": "客队",
    "competition": "赛事",
    "date": "2026-10-10",
    "source": "官方数据",
    "coordinateSystem": "feet-center-attacking-negative-x"
  },
  "shots": []
}
```

`shots` 必须包含 1–500 个出手机会。上面的空数组仅说明结构，不能直接导入。

## 每次出手

| 字段 | 要求 |
|---|---|
| `id` | 文件内唯一的非空字符串 |
| `shooterId` / `shooterName` | 出手球员字符串 ID、姓名 |
| `offenseId` / `team` | 进攻队字符串 ID、队名 |
| `period` / `gameClock` | 节数（整数 ≥1）；该节剩余秒数（0–720） |
| `outcome` | `made`、`missed`、`unknown` |
| `points` | 可选，2 或 3；只用于显示，不参与评分 |
| `shotQuality` | 可选，0–100；缺失用 `null`，不是命中率 |
| `defenderDistance` | 可选，出手时最近防守距离，英尺，缺失用 `null` |
| `players` | 同一出手时刻的球员点位数组，缺失用 `[]` |
| `frame` / `videoTimeMs` | 可选，源帧号 / 原视频毫秒，供后续视频对齐 |
| `chanceId` / `possessionId` | 可选，便于关联事件，但不以此伪造完整回合分析 |

## 每个球员点位

| 字段 | 要求 |
|---|---|
| `id` / `teamId` | 字符串；与出手球员、进攻队 ID 保持一致 |
| `name` / `jersey` | 字符串姓名和球衣号码（包括 `"0"`） |
| `x` / `y` | 英尺，中心原点，进攻篮筐在负 x；有限数值 |
| `detected` | `true` 为直接检测，`false` 为数据方外推，未知为 `null` |
| `errorFt` | 非负位置误差估计，英尺；未知为 `null` |

需要 5 名同队进攻球员、5 名同队防守球员，且出手者在进攻数组中，才计算指数。质量信息缺失仍可计算几何关系，但不能进入默认精选。

## 适配原则

- 不把缺失指标设置为 0；0 是有效数值，缺失用 `null`。
- 不从单个快照补造速度、轨迹、掩护过程或空间变化。
- 官方 Gravity 如果定义不同，保留为独立指标；当前自定义指数不能直接替代它。
- 赛方指标不一定等同 SkillCorner 指标，尤其投篮难度、质量与命中概率。先核对定义再映射，不能仅改字段名。
- 可保留额外的源字段用于追溯，分析器不会把额外字段自动用于评分。
- 重新导入已有导出结果时，服务端会重新计算 `analysis`，不信任文件中原有分数。
